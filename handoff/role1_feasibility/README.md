# 一号位：训练侧决策空间小试验（2026-11-27）

## 范围与复现材料

只使用冻结的 **train** 任务 R005（易）、R001（中）、R022（难），每题每路线真实执行一次。四条预先指定路线是 `raw_fast`（检索、直接写）、`rule`（检索、快速总结、快速写）、`retrieve_again`（检索、快速总结、再检索、深度总结、快速写）、`deep`（检索、深度总结、深度写）。所有运行调用官方 DeepSeek API，终稿在全部轨迹完成后才交给冻结的 `deepseek-v4-pro` Judge。Judge 输入不含路线名。配置及原始轨迹分别见 `plan.json`、`episodes/`、`execution_complete.json`；完整评分请求和回执见 `judge_receipts/`，验证后标签见 `labels/`，汇总见 `scores.json`。`traces/` 是运行时副本，保存在本地 `outputs/decision-feasibility-v1-20261127/`，未重复归档。

12/12 条轨迹成功且校验通过，12/12 个 Judge 标签有效。`total_workflow_tokens` 是各步报告的工作流 Token 之和；下表是原始值，分数是四项 Judge 分数的平均值，不是训练奖励或统计显著性结论。

## 第二次检索确实增加了证据，但评分未反映

用 `evaluation/train_criteria.json` 的训练侧证据清单做**离线诊断**，只数与题目标准相关的不同论文 ID，不将这些 ID 数当成正式质量分数，也不把清单视作穷尽的相关文献。

| 任务 | 清单中的论文数 | 首次检索命中 | 再检索后命中 | 直接写 / 再检索 Judge 分 |
| --- | ---: | ---: | ---: | ---: |
| R005 | 1 | 1 | 1 | 0.95 / 0.95 |
| R001 | 4 | 3 | 4 | 0.95 / 0.95 |
| R022 | 4 | 2 | 4 | 0.95 / 0.94 |

R001 和 R022 的第二次检索补回了清单中的全部论文，并在终稿正文中引用了它们。R022 的补回论文包括 `1807.11174v1` 和 `2008.02646v1`；后者摘要提供了“四项任务在仿真中均能学习、实机上三项能学习”的边界证据。当前 Judge 的 `coverage` 按题面回答程度评分，不按论文匹配率；请求中只列出终稿**已引用**论文的冻结摘要，未给 Judge 全库和遗漏清单。因此分数没有展示额外检索的价值，不能单凭高分断言漏掉的论文不重要。这也不能证明 Judge 评错了：题面可能由首批论文充分回答。正式质量、证据覆盖和成本应分开观察。

## 正文信息增益小探针

另用开放论文 [2008.02646v1](https://arxiv.org/pdf/2008.02646v1) 的讨论章节（PDF 第 7 页，X. DISCUSSION）做**非正式、单篇、单次**对照。问题要求指出提高实机训练样本效率的具体技术、幅度以及效果明显的任务。同一 `deepseek-flash` 模型和提问，分别只给题名与摘要、再加讨论段落。摘要条件回答“材料未说明”，`sufficient=false`，耗 483 Token；加段落后回答 HER、最高约 10 倍、字母表任务，给出所给段落中的连续原文证据，`sufficient=true`，耗 576 Token。摘要本身没有这个方法与幅度。原始响应保存在本地 `outputs/decision-feasibility-v1-20261127/fulltext_diagnostic.json`，归档中的 `fulltext_diagnostic_summary.json` 留存可复核的简表、来源和段落 SHA-256。

这个小探针只验证“读正文”可能增加可用信息；它没有运行新的 Runner 动作，也没有使用冻结 Judge 评分，不与上表直接比较，更不能证明何时打开正文的策略已经可训练。

## 对架构的判定与下一步

目前五个动作中，再检索始终使用原题面作为查询，不能根据中间摘要改写检索词；快速/深度与是否先总结的选择，在这三题上也没有产生可测的质量收益。**维持 V1 作为已冻结的摘要基线，但暂不把这组结果当成训练 DQN 的正向证据。** 二号位可用这些轨迹检查接口和成本记录，不宜把本试验的 12 个高分当成足够的策略学习标签。

要评估可训练的 V2，应由三号位单独冻结正文段落及其来源位置、可回答性和缺失证据标注；一号位再增加“按缺口改写检索词”“按需打开论文指定章节”“停止收集并写作”等有真实信息差和成本的动作；Judge 应能看见必要的证据范围，并先用人工核对的漏答、错引反例验证评分敏感性。V2 的任务、动作、Judge 与版本均应另行封存，不把 V1 摘要分数混入 V2 训练或测试。

运行脚本：`python -m experiments.feasibility run --output <new-dir>`，完整完成后 `python -m experiments.feasibility judge --output <same-dir>`。这两个命令会发起真实 API 请求；本次已完成，无须重跑。
